The 5 functionalities from Part 1, traced end to end: the Jira story that defines each one, the manual test cases written against it, the Playwright spec that automates it, and where its real evidence actually lives. This is the single page that answers "does a check exist for this, and did it pass."

Reading the last column honestly

Every spec exists, is checked into e2e/src/tests/, and runs on every pull request per the automation status table. The red badges above are not a gap in automation, they are a real, captured failure: a bounded run of registration.spec.ts, login.spec.ts and api-keys.spec.ts against the live stack scored 0 of 38 passing, each for a different concrete reason (a missing test-id on /register, a cleanup bug that leaves emails registered, a login that never completes within 60s). See the full breakdown and raw output on the e2e-frontend evidence page.

chat-management.spec.ts and attach-file.spec.ts were not part of that bounded run, so this report has no fresh automated pass/fail for them. What it does have is real, manually captured screenshots of both flows working on the live app, on The Project page. That is a weaker form of evidence than a green CI run, and this page says so rather than implying otherwise.
