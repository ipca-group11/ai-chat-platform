Black-box vs White-box Testing

Black-box tests treat the app as a sealed box. They only use what a user or an API caller could: clicks, requests, responses, with no knowledge of the code inside.

White-box tests know the internals. They read the source, inspect the database directly, or check what's actually written to a log.

Most of the test case design in Part 1 (boundary values, equivalence classes) is a black-box technique, since it only needs the requirement, not the code. A few epics here sit in between (contract and integration tests use real code with fakes swapped in); they're listed wherever the stronger pull is.
