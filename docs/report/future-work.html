Appendix

Future Work & Roadmap

This report covers the testing delivered so far: the 5 functionalities from Part 1 and Part 2, the wider strategy, and 30 test types with real evidence. This page is about what comes next, and one piece of it that is already underway.

In progress now: prompt testing

Prompt and response quality testing In progress

The security side of prompts is already covered: the prompt-injection epic checks that a malicious message cannot make the assistant ignore its own rules or leak another user's data. What is not covered yet is the quality of a normal, well-behaved reply.

This is being built as its own test type, separate from functional and security testing, because it tests the model's output rather than the application's code. The plan is a small fixed set of representative prompts, a golden or acceptable-range answer for each, and an automated check, either a rule-based match or a second model acting as a judge, that scores each real reply against that expectation. The suite would run whenever a prompt template, a model choice, or a provider adapter changes, so a regression in answer quality is caught the same way a regression in code is caught today.

This work is not finished. It will be delivered as its own epic on the Jira board, with its own test type page in this report, once the first version of the suite is running in CI.

Roadmap

"Next" is the only column already underway, the prompt testing work described above. "Later" is scoped but not started, and is ordered by what the NFR page already names as lower priority for this project: Compatibility and Portability over Usability polish such as visual regression.

Other gaps worth naming

Visual regression

The test type exists and is wired into CI, but has no approved baseline screenshots yet, so it currently has nothing to compare against.

Cross-browser coverage

Playwright currently runs one browser project. Firefox and WebKit projects would catch engine-specific rendering or SSE handling differences.

Chaos and synthetic monitoring

Resilience is tested in controlled conditions today (remote failure, SSE drop, cancellation). Nothing yet injects faults into the live production VM or watches it continuously.

Due dates on the Jira board

Priority and due dates have been set on the epics but not yet rolled out across every one of the 169 underlying stories.
