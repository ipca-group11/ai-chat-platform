Part 1

Requirements & Test Cases

Five functionalities of the AI Chat Platform, each described with its own acceptance criteria and a test case table ordered by execution priority. Every test case names the technique used to design it: Boundary Value Analysis for anything with a numeric or length limit, and Equivalence Partitioning for anything with distinct valid/invalid classes of input. P1 is the happy path plus the boundary that would break the feature outright; P2 covers the remaining invalid-class and error-path cases.

1. Sign up 2. Log in 3. Add a provider API key 4. Create chats & send messages 5. Attach a file

1. Sign up with email and password

AICHAT-223 ↗

As someone opening the app for the first time, I want to create an account with my email and a password, so I can start using the chat platform.

Inputs
  • Email, required, valid format, unique
  • Password, required, 8–128 chars, upper + lower + digit
  • Confirm password, must match
Acceptance criteria
  • A valid, unused email + a password meeting the rules creates the account.
  • An email already in use is rejected, no duplicate account created.
  • A password under 8 characters is blocked client-side, before any request.
  • A mismatched confirm-password is rejected with a clear error.

2. Log in to the app

AICHAT-224 ↗

As a returning user, I want to log in with my email and password, so I can get back into my account and continue my conversations.

Inputs
  • Email address
  • Password
Acceptance criteria
  • Correct credentials log the user in and land on the chat screen.
  • A wrong password shows one generic error, without revealing whether the email exists.
  • Repeated failed attempts get throttled instead of allowed forever.

3. Add a provider API key

AICHAT-225 ↗

As a user, I want to add my own API key for an AI provider, so the app can generate chat responses on my behalf, billed to my own account.

Inputs
  • Provider, Anthropic or OpenAI
  • API key value, provider-specific format, ~20–200 chars
Acceptance criteria
  • A valid, working key is saved and shown masked.
  • A revoked or invalid key fails validation and nothing is saved.
  • The key is never shown in full again, nor logged.

4. Create chats and send messages

AICHAT-226 ↗

As a user, I want to start a chat and send messages in it, so I can have a conversation with the AI assistant. The core of the app.

Inputs
  • Message text, 1 to 32,000 characters
  • An existing chat, or a new one being started
Acceptance criteria
  • A new chat can be started and a first message sent.
  • A sent message appears right away, the reply streams in live.
  • A message right at the 32,000-character limit is accepted; longer is rejected clearly.
  • An empty message can't be sent.

TC6P2Equivalence PartitioningSend to a chat not owned by the user (invalid class)403/404, nothing persisted

5. Attach a file to a message

AICHAT-227 ↗

As a user, I want to attach a file to my message, so I can share something with the AI assistant alongside my text.

Inputs
  • A file, .txt, .pdf, .png, .jpg/.jpeg, up to 10 MB
Acceptance criteria
  • An allowed file under the size limit uploads and sends with the message.
  • A too-large file is rejected before upload, with a clear size error.
  • An unsupported file type is rejected with a clear type error.
