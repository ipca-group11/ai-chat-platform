What it checks

Full epic details, from Jira

Description

This epic covers testing the auth and conversation services at the HTTP level - sending real requests into the Express app and checking the responses, with the database, queue, and provider connections swapped for fast in-memory stand-ins. It sits between the narrow unit tests that check one function at a time and the full end-to-end tests that drive the whole app through a browser, and it's where most of the bugs in how routes are wired together and how business rules conflict with each other actually get caught.

Inputs
  • Requests to each service's routes, with realistic and deliberately invalid bodies
  • Fake versions of the provider registry, job queue, and database that the app can be started with instead of the real ones
Acceptance Criteria
  • Every route across both services returns the right success response for valid input and the right, specific error for invalid or conflicting input.
  • Failures that nobody anticipated are turned into a safe, generic response rather than leaking internal details.
  • A new route added without a matching test is caught automatically rather than slipping through unnoticed.
Tooling / Tech Stack
  • Supertest driving the real Express apps
  • Vitest as the test runner
  • In-memory fakes in place of Postgres, the job queue, and the LLM providers
Definition of Ready
  • Both services can be started with their real dependencies swapped out for fakes.
Definition of Done
  • The scenarios above run automatically as part of the normal test suite, and a failure blocks the merge.
  • Evidence of the tests passing is visible on the individual pieces of work underneath this one.
