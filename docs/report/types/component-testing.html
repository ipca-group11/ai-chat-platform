What it checks

Composer, ChatView and settings: render, interaction and error states. Checked with Testing Library's user-centric queries instead of reaching into internals.

Every pull request.

Full epic details, from Jira

Description

Test the key React components of the AI chat platform's interface - the message composer, the chat view, and the settings provider list - in isolation, checking how they render, respond to interaction, and handle error states. This closes a real gap: live message streaming was never actually exercised in these tests, because the fake stream implementation used before never emitted anything, leaving a number of states effectively untested.

Inputs
  • Component props and state (loading, error, populated, empty)
  • Simulated user interactions - typing, sending, attaching a file, adding a provider key
  • A simulated SSE stream for anything that depends on live updates
Acceptance Criteria
  • Each component renders correctly for its normal, loading, empty, and error states.
  • Interactive behaviour - sending a message, queueing one, attaching a file, adding a provider - works as expected and surfaces a clear error on invalid input.
  • Live streaming updates are shown correctly as they arrive, not just once the stream finishes.
  • Every tested state also passes an accessibility check with no serious violations.
Tooling / Tech Stack
  • React Testing Library with Vitest, using user-centric queries over implementation details
  • A reusable fake EventSource for simulating SSE streams
  • axe-core for accessibility checks, integrated into the same tests
Definition of Ready
  • The underlying mock backend and unit-test setup this area builds on are already in place.
Definition of Done
  • All the acceptance criteria above pass automatically in CI.
  • A failure here blocks the merge.
  • Any state deliberately left uncovered is called out rather than silently skipped.
