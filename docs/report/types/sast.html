Security Non-functional White-box
What it checks

Static analysis of the source code itself, looking for the kind of vulnerability patterns a human reviewer would miss on a big diff.

Tooling
  • Semgrep / CodeQL
Cadence

Every pull request; a high-severity finding blocks the merge.

Full epic details, from Jira

Description

This epic adds static analysis to the codebase so insecure patterns, like hardcoded secrets or an unprotected endpoint, get caught in the source before they ever reach main, rather than being found later in production or during a pentest. It covers choosing a tool, configuring real rules for this stack, cleaning up what the first scan finds, and turning the scan into a gate that actually blocks a bad pull request.

Inputs
  • Source code across the frontend shell, micro-frontends, and backend services
  • Pull request events and their diffs
  • Rule packs and custom rules tuned to this stack's known risk patterns
Acceptance Criteria
  • A tool is chosen and configured with rule packs and custom rules relevant to this codebase.
  • Findings already present in the codebase are triaged, so the gate starts from a clean, understood baseline.
  • A pull request introducing a new high-severity issue, like a hardcoded secret, is blocked from merging.
  • Findings show up in the pull request in a form a developer can actually read and act on.
Tooling / Tech Stack
  • Semgrep CE
  • GitHub Actions, running the scan as a required check on every pull request
Definition of Ready
  • The tool choice and its licensing fit for a private repo are agreed.
Definition of Done
  • The scan runs automatically on every pull request.
  • A new high-severity finding blocks the merge; anything not yet automated is called out rather than hidden.
