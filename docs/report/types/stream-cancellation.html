Functional Tests/Stream cancellation testing

Stream cancellation testing

View on Jira, AICHAT-15 ↗ How to run → Evidence →
Core user flows Functional Black-box
What it checks

Stopping a reply or navigating away mid-answer has to actually close the connection to the provider upstream, not just hide it in the UI while the model keeps generating (and getting paid for) tokens nobody will see.

Tooling
  • Vitest with a mock LLM server that records the connection close
Cadence

Every pull request.

Full epic details, from Jira

Description

Stream cancellation is what makes the "Stop" button on a chat reply trustworthy. This area of testing covers the whole path a cancellation has to travel: the request that tells the backend to stop, the abort actually reaching the LLM provider call, the provider connection genuinely closing, and the partially-generated reply being saved and shown correctly as stopped rather than silently vanishing or carrying on in the background.

Inputs
  • A stop request fired from the chat UI against an in-flight streaming reply
  • The active provider adapter and its underlying connection to the LLM
  • Partial reply content generated up to the moment of cancellation
  • Browser navigation and tab-close events that might happen mid-stream
Acceptance Criteria
  • Stopping a reply reliably stops the backend from generating further content and actually closes the connection to the provider, not just the UI.
  • A stopped reply is saved with whatever content was generated so far and clearly shown as stopped, distinct from a normal completed reply.
  • Leaving a conversation mid-stream, whether by switching chats or closing the tab, also stops the generation rather than leaving it running unattended.
  • The automated test proving all this checks the real signal that the connection closed, not just that the Stop button didn't error in the UI.
Tooling / Tech Stack
  • Playwright for the end-to-end cancellation flow
  • Vitest for the Stop endpoint, provider adapter, and persistence logic
  • A mock LLM server with a controllable delay and a connection-close inspection endpoint, standing in for the real provider
Definition of Ready
  • The chat send/receive flow and the mock LLM server already exist, since cancellation testing has nothing to cancel without them.
Definition of Done
  • All child stories' acceptance criteria pass automatically.
  • This test type runs in CI and a failure blocks the merge.
  • Evidence of the test runs is linked from each child story.
