Non-Functional Tests/Bundle size budget testing

Bundle size budget testing

View on Jira, AICHAT-22 ↗ How to run → Evidence →
Non-functional Non-functional White-box
What it checks

How much JavaScript each micro-frontend actually ships, checked against a size budget so one dependency doesn't quietly bloat every page load.

Tooling
  • size-limit
Cadence

Every pull request; going over the budget fails CI.

Full epic details, from Jira

Description

The frontend is split into a shell plus three independently-loaded remotes for auth, chat, and settings, and nothing stops any of them from quietly growing until the app feels slow to load. Bundle size budget testing puts a ceiling on each remote's gzip size and checks real build output against it on every change, so a size regression is caught before it reaches users rather than being noticed later as a vague "the app feels sluggish" complaint. It matters most for the shell and chat remotes, since those sit directly on the path to a user seeing the chat screen and getting their first reply.

Inputs
  • Build output for each remote (its main entry file and any lazy-loaded chunks)
  • The agreed size ceiling for each remote
  • How each remote declares and shares its common libraries (React, the design-system package, etc.)
Acceptance Criteria
  • Each remote has an agreed, documented size limit, and real build output is measured against it automatically.
  • A change that pushes a remote over its limit fails the build and blocks the merge.
  • Anyone opening a pull request can see the size impact of their change without running anything locally.
  • Shared libraries load once across the whole app, so the per-remote limits reflect real user-facing weight rather than hidden duplication.
Tooling / Tech Stack
  • Nx build targets and task graph, instrumented to report gzip size
  • CI pipeline gating and pull-request comments
  • Module Federation's shared-dependency configuration
Definition of Ready
  • The remotes already build successfully and produce real output to measure.
Definition of Done
  • Size is measured automatically on every relevant build and enforced as a CI gate.
  • Anything not yet automated is called out on its own story rather than assumed done.
