Chat correctness Functional White-box
What it checks

Replays real, recorded Anthropic and OpenAI streams: plain text, thinking blocks, truncated answers, provider errors. This proves the chat UI handles every response shape correctly, without ever calling a real, paid model.

Tooling
  • Vitest
  • Recorded SSE fixtures
  • A guard that fails on any real network call
Cadence

Every pull request.

Testing strategy

One spec, recorded-replay.spec.ts, drives the real Anthropic and OpenAI adapter code against 20 recorded or hand-written fixtures (12 for Anthropic, 8 for OpenAI) stored in test-utils/fixtures/llm. Each streaming fixture is replayed three times, once per chunk layout, so the same bytes get cut differently every pass: an uneven cycle of 1, 7, 64, 3 bytes, one byte at a time, and the whole body in one piece. That is on purpose: multi-byte UTF-8 characters in the fixtures (ça, atenção, 😀) land on different byte boundaries depending on the layout, so the adapter has to reassemble them correctly no matter where the network happened to cut.

CaseCovers
text, text-ping, thinkingPlain text deltas, ignored ping events, reasoning blocks before the answer
max-tokensA truncated answer streamed like a complete one (tracked as AICHAT-212)
web-fetch-error, pause-turn-1/2A server-side tool error, and resuming a paused turn with the reply built so far
overloaded-midstream, error-midstreamPartial text followed by a mid-stream failure, one retryable, one swallowed today (AICHAT-211)
HTTP errors8 cases: status 400/401/429/529 for Anthropic, 400/401/429/500 for OpenAI, each asserted for message and the retryable flag

Nothing here touches the network: replayFetch hands the adapter a fake fetch that serves the fixture bytes and records the outgoing request bodies, which is how the pause-turn test checks the exact continuation payload the adapter sends back. Two known defects, AICHAT-211 and AICHAT-212, are asserted as today's actual behaviour with an it.todo describing the fix, so the suite documents the bug instead of hiding it.

Full epic details, from Jira

Description

This epic covers how the chat app's two LLM provider adapters, Anthropic and OpenAI, are tested against realistic streaming behaviour rather than idealized mocks. Real streams don't arrive as one clean message - they come in uneven chunks, sometimes pause, sometimes get truncated, and sometimes fail partway through. By recording real provider responses once and replaying them with randomized chunking, these tests catch adapter bugs that only show up under messy, real-world network conditions, all without ever making a live API call during a test run.

Inputs
  • Recorded streaming responses from both providers, covering plain text, thinking, a paused turn, a token-limit cutoff, and a mid-stream error
  • Those recordings replayed in varying byte-sized chunks to mimic real network delivery
Acceptance Criteria
  • Both providers' adapters correctly handle text, thinking, paused turns, token-limit truncation, and mid-stream errors when replayed from recorded fixtures.
  • A truncated or failed response is reported as incomplete rather than shown to the user as a finished answer.
  • Chunk boundaries never change the outcome, whether an event arrives in one piece or several.
  • No test in this suite ever makes a real network call.
Tooling / Tech Stack
  • Vitest for the adapter and UI tests
  • A small recording script and a byte-offset replay helper built specifically for this fixture set
  • A network guard that fails any test attempting a real outbound call
Definition of Ready
  • There's a way to get a real API key for each provider to record fixtures once.
  • The scenarios that matter (text, thinking, paused, truncated, errored) are agreed.
Definition of Done
  • The full suite runs automatically in CI on every pull request with zero live network calls.
  • A failure anywhere in this suite blocks the merge.
  • Known gaps in provider stream handling are caught by a regression test rather than left unverified.
