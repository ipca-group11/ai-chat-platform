Full epic details, from Jira

Description

This epic covers the platform's GDPR obligations around data retention and account deletion: making sure old data doesn't get kept longer than it should, and that deleting an account actually removes everything tied to it - chats, messages, files and telemetry - rather than leaving fragments behind. These aren't nice-to-haves; they're legal requirements, and getting them wrong has real consequences for users and for the business.

Inputs
  • Agreed retention periods for different kinds of stored data, such as chats, files and telemetry logs
  • Test databases seeded with data at different ages relative to those retention periods
  • Account deletion requests exercised against a real database and file storage layer
Acceptance Criteria
  • Retention periods for every kind of stored data are agreed, documented and enforced by a tested job.
  • Deleting an account removes all of that user's chats, messages, files and related data, verified against a real database rather than assumed.
  • Data is purged right at its retention cutoff, not noticeably early or late.
  • Misconfigured retention settings are caught automatically rather than silently reaching production.
Tooling / Tech Stack
  • Testcontainers with a real Postgres instance for database-backed verification
  • Integration test suites covering deletion and retention behaviour
  • Configuration tests for deployment-level retention settings
Definition of Ready
  • Retention periods and deletion rules are agreed before any of the underlying tests or code are built.
Definition of Done
  • Every piece of deletion and retention behaviour in this area is covered by an automated test that runs continuously.
  • A failing test blocks the merge, since this is a compliance control, not an optional check.
