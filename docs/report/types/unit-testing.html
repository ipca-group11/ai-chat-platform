Full epic details, from Jira

Description

Unit testing is the base layer of testing for this platform - fast, isolated tests that check individual functions, hooks and controllers in each app and service, without needing a browser, a real database or a live AI provider. This epic covers that base layer across the whole monorepo: every frontend app, every backend service, and the shared packages in between, plus the policy and tooling that keeps new code from shipping without a test.

Inputs
  • The source files across the frontend apps, backend services and shared packages
  • The policy defining what must be tested and what's reasonably exempt
  • Shared test helpers and mocks used across all of the above
Acceptance Criteria
  • Every app and service has either a passing unit test for each source file or a documented, agreed exemption.
  • Shared logic like the model capability tables and validation utilities is checked for correctness and internal consistency, not just "does it run."
  • A guard check keeps new, untested files from merging once the policy is in place.
  • The frontend's and backend's views of what each AI model supports stay in sync with each other.
Tooling / Tech Stack
  • Vitest as the test runner across the whole monorepo
  • Testing Library for frontend component and hook tests
  • supertest for backend controller and middleware tests
Definition of Ready
  • The unit-test policy and exempt list are agreed before the bulk of the coverage work starts.
Definition of Done
  • Unit tests run automatically in CI on every pull request and a failure blocks the merge.
  • Coverage is complete across every app, service and shared package, with any exemptions documented rather than silent.
