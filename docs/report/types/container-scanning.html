Non-Functional Tests/Container image scanning

Container image scanning

View on Jira, AICHAT-7 ↗ How to run →
Security Non-functional White-box
What it checks

Every Docker image is scanned for known CVEs before it's pushed anywhere. It checks the image itself, not just the source that built it.

Tooling
  • Trivy
Cadence

Every image build; a high-severity CVE blocks the deploy.

Full epic details, from Jira

Description

This epic covers scanning every container image the platform builds (the shell app, the auth, chat and settings micro-frontends, and the auth and conversation services) for known vulnerabilities in their operating system packages and dependency layers before an image is allowed to reach the registry or production. A vulnerable base image or an outdated system package can introduce a serious security hole without any change to the application's own code, so catching that at build time rather than after deploy matters.

Inputs
  • The built container image for each service, ready to push
  • The vulnerability database the scanner checks against
  • The severity level a finding needs to reach before it blocks anything
Acceptance Criteria
  • Every image is scanned automatically as part of the deploy pipeline before it is pushed.
  • An image with a high or critical vulnerability fails the pipeline and is not pushed or deployed.
  • An image with no high or critical findings passes and continues through the pipeline normally.
  • The scan results are kept so anyone can see what was found on a given run.
Tooling / Tech Stack
  • Trivy, scanning each built image for OS and dependency vulnerabilities
  • GitHub Actions, running the scan as a step in the deploy workflow
Definition of Ready
  • The severity level that blocks a deploy (high and critical) is agreed.
Definition of Done
  • The scan runs automatically on every image build and a high or critical finding blocks the deploy.
  • The scan output is kept as part of the pipeline run so it can be reviewed later.
