Non-Functional Tests/PII masking testing

PII masking testing

View on Jira, AICHAT-32 ↗ How to run → Evidence →
Security Non-functional White-box
What it checks

Emails, IP addresses and message content, checked across logs, metrics and telemetry. None of it should ever show up raw.

Tooling
  • Vitest with log capture
  • A reusable PII detector helper
Cadence

Every pull request.

Full epic details, from Jira

Description

This covers making sure personal data never leaks out through the places the platform exposes for operability - the logs written by the auth and conversation services, the metrics endpoint scraped by Prometheus, and the browser telemetry shipped to Grafana. Anyone with access to logs, dashboards, or telemetry should be able to do their job without ever seeing a user's email, IP address, chat content, or session token in the raw.

Inputs
  • Service logs, metrics output, and browser telemetry payloads as they're actually emitted
  • The agreed list of personal-data fields and the masking rule for each one
  • A shared way of scanning any of the above for personal data that got missed
Acceptance Criteria
  • Logs from the auth and conversation services never contain raw emails, IP addresses, message content, or session tokens.
  • The metrics endpoint never exposes personal data through label values.
  • Browser telemetry is scrubbed of personal data before it leaves the user's machine.
  • A shared detector can scan any of these outputs and reliably catch personal data that slipped through, including at the edges of size limits.
  • Any leak found in CI blocks the merge rather than being waved through.
Tooling / Tech Stack
  • pino-http for structured service logging
  • The Prometheus client library for metrics
  • Grafana Faro Web SDK for browser telemetry
  • A shared PII-detection helper reused across all of the above, verified with Playwright where browser behaviour is involved
Definition of Ready
  • The team has agreed which fields count as personal data and what should happen to each one.
Definition of Done
  • All of the checks above run automatically in CI, and a personal-data leak in any of these outputs fails the build rather than going unnoticed.
