Non-Functional Tests/Dependency vulnerability scanning (SCA)

Dependency vulnerability scanning (SCA)

View on Jira, AICHAT-6 ↗ How to run → Evidence →
Security Non-functional White-box
What it checks

Known CVEs in the npm packages this project depends on, so a vulnerable library doesn't sit there unnoticed.

Tooling
  • pnpm audit
  • Dependabot
Cadence

Every pull request, plus automatic weekly dependency update PRs.

Full epic details, from Jira

Description

This covers software composition analysis for the platform: keeping an eye on the third-party npm packages used across the Next.js micro-frontends and the backend services, and catching known vulnerabilities in them before they reach production. Dependencies are often where exploitable bugs sneak in without anyone writing a line of vulnerable code themselves, so this is about making sure the libraries we pull in stay trustworthy over time, not just at the moment they were first installed.

Inputs
  • The dependency tree resolved for each workspace in the monorepo
  • Published vulnerability advisories for npm packages
  • The severity level of each advisory found
Acceptance Criteria
  • Every pull request and push to the main branch triggers a dependency audit across all workspaces.
  • A high or critical severity finding fails the build and blocks the merge.
  • Lower-severity findings are visible but don't block anything.
  • Dependencies are checked on an ongoing schedule, not just at the moment a PR is opened, so a newly disclosed vulnerability in an already-merged package gets flagged too.
  • Any high/critical advisory present when this work started has been fixed or has a documented reason for being left as is.
Tooling / Tech Stack
  • pnpm audit, run as part of the CI pipeline
  • Dependabot, for scheduled dependency update and alerting
Definition of Ready
  • The severity threshold that blocks a merge is agreed.
Definition of Done
  • The audit runs automatically on every PR and push to main, and a high/critical finding blocks the merge.
  • Dependabot is enabled and alerting on a recurring schedule.
  • Known high/critical advisories at kickoff were resolved or explicitly waived with a reason.
