Tech Stack

The full set of languages, frameworks and tools the AI Chat Platform is built with. Source: docs/STACK.md.

Language & runtime
  • TypeScript, across frontend and backend
  • Node.js
  • pnpm workspaces (monorepo)
  • Nx: project graph, cached tasks, nx affected in CI
Frontend
  • React, built with Vite
  • Micro-frontends via Vite Module Federation: one shell host plus one remote per domain (auth, chat, settings)
  • TanStack Router for type-safe, file-based routes
  • TanStack Query for server state
  • shadcn/ui on Base UI primitives, styled with Tailwind CSS
  • Design system in packages/ui, documented in Storybook
Backend
  • Express, with helmet, cors and express-rate-limit
  • Postgres, via Prisma
  • JWT access tokens (15 min) plus a rotating refresh token (7 days), both as httpOnly cookies
  • bcrypt for password hashing
  • Zod for request/response validation, schemas shared from packages/shared-types
  • Server-sent events for streamed chat replies
Testing
  • Vitest, for unit, component, integration and snapshot tests
  • Playwright, for end-to-end tests
  • axe-core, for accessibility
  • Pact, for consumer-driven contract tests
  • k6, for load tests
Containers & infrastructure
  • Docker and Docker Compose, the whole system starts with one docker compose up
  • GitHub Actions for CI, GHCR for image storage
  • An Azure VM as the production host, behind Caddy as a TLS-terminating reverse proxy
Observability
  • Prometheus for metrics, scraping each service's /metrics endpoint
  • Grafana for dashboards
  • Loki for log aggregation, Grafana Alloy as the collector
  • pino structured JSON logging with a correlation ID on every request

Why these choices

Micro-frontends, not one app

Auth, chat and settings ship and deploy independently. A broken remote shouldn't be able to take down the other two, which is exactly what the remote-failure test type checks.

Server-sent events over WebSockets

Chat replies only flow one way, from the server to the browser. SSE is simpler than a full duplex connection and plays well with standard HTTP infrastructure and proxies.

Provider keys stay in the browser

Anthropic and OpenAI API keys are entered per-user in Settings and sent per-request. They are never stored server-side, which removes an entire class of data-breach risk.
