Functional Tests

Functional Tests

Checks what the app does: does a feature behave the way the requirement says? There are 14 test types here, including the mock server they all run against.

Unit testingAICHAT-17

Hooks, utilities, service logic and model capability tables, tested in isolation.
Component testingAICHAT-18

Composer, ChatView, settings, render, interaction and error states.
Snapshot testingAICHAT-20

Only small, stable outputs, serialized DTOs and SSE frames, nothing larger.
Integration testingAICHAT-23

Every Express route against real code, with fake repositories for the database.
Consumer-driven contract testingAICHAT-11

Each micro-frontend's expectations replayed against the real service code.
API schema validation testingAICHAT-12

Requests and responses checked against the shared Zod schemas.
Provider adapter testingAICHAT-25

Replays recorded Anthropic/OpenAI streams, no live model call needed.
E2E testing, frontend flowsAICHAT-4

The 5 functionalities from Part 1, driven through a real browser.
E2E testing, backend flowsAICHAT-5

The same journeys, checked at the backend afterwards.
Remote failure and fallback testingAICHAT-8

A micro-frontend remote goes down, does the rest of the app still work?
SSE reconnection testingAICHAT-9

The network drops mid-stream, resume, or a clear error, never a hang.
Concurrency testingAICHAT-13

Two sends at once, or a retry mid-stream, no duplicate or lost messages.
Stream cancellation testingAICHAT-15

Stopping a reply actually aborts the call upstream, not just in the UI.
Mock serverAICHAT-144

Stands in for the real backend and the LLM provider, so every layer above can run without a database or an API key.
