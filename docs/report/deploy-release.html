Deploy & Release

What happens between a merge to main and the app being live, how to roll back, and how to stop a local run. Source: .github/workflows/deploy.yml, docs/DEPLOY.md.

From merge to production

The deploy workflow triggers after CI succeeds on main, or by hand. The VM never builds anything: it only pulls images already tagged with that commit's SHA, then reloads Caddy and runs a smoke test against the public URL.

A HIGH or CRITICAL Trivy finding on any image stops the deploy before it reaches GHCR. The SBOM/Grype step reports known vulnerabilities but does not block, that gate belongs to the Trivy step.

Rolling back

Re-run the deploy workflow by hand against an older commit SHA (Actions, deploy, Run workflow). The VM pulls that commit's already-built, already-scanned images from GHCR, so a rollback is just pointing the VM at a different tag, no rebuild needed.

Stop it

Terminal
docker compose -f compose.yaml down          # stop and remove containers
docker compose -f compose.yaml down -v       # also remove volumes (Postgres data, uploads, Grafana)
